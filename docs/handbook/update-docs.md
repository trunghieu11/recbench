# Update the docs

!!! abstract "In plain words"
    The docs are part of the work: a result nobody can find, or an explanation that is now wrong, costs the next
    reader hours. Some pages are hand-written; tables of numbers are **generated** from results and must not be
    edited by hand. After a lab you update three things: the lab page's results table (by hand), the scoreboard
    (generated), and the method's page where your change matters (by hand).

## What to update after a lab

| What | Where | How |
|---|---|---|
| your results and what you learned | the lab page's "Record your results" section, `docs/labs/<nn>-<method>.md` | by hand: one row per experiment, plus two or three sentences of conclusion |
| the numbers | `docs/generated/lab/*.md` (shown on the lab page and the [scoreboard](../labs/scoreboard.md)) | `python -m recbench.lab scoreboard --docs` |
| the method's description | `docs/dictionary/algorithms/<method>.md` | by hand, when your change affects it: a new setting in **Hyperparameters**, a new pitfall, a promoted variant in **In recbench** |
| a new term | `docs/dictionary/concepts/glossary.md` | by hand, in alphabetical order |

!!! warning "Never edit files in `docs/generated/` by hand"
    They are rebuilt from results and your edits would be overwritten. Each one starts with
    `<!-- generated by ... -->`, which names the command that writes it.

## See your changes

```bash
mkdocs serve
```

Open <http://127.0.0.1:8000>. The page reloads whenever you save a file. Stop with Ctrl-C.

## Check them

```bash
pytest -q tests/test_docs.py
```

These checks fail on the mistakes that are easy to make and hard to spot:

| Check | Fails when |
|---|---|
| commands and flags | a page shows `python -m recbench...` with a flag the code does not accept |
| scripts | a page mentions a `scripts/*.sh` file that does not exist |
| code pointers | a page points at `src/recbench/....py::name` that does not exist |
| lab pages | a lab page misses a section, the hint and solution boxes, or its generated starting point |
| counts | a page says "N methods" and the code has another number |
| the build | a link, an anchor or an included fragment is broken (`mkdocs build --strict`) |

## Writing style used on this site

- Start a new page with an **In plain words** box: what it is about and why it matters, without jargon.
- Explain the intuition before the formula, and give a small worked example with real numbers.
- Show real output in a **You should see** box, so the reader can check their own.
- Define a term the first time you use it, or link to the [glossary](../dictionary/concepts/glossary.md).
- Short sentences. One idea per paragraph.
